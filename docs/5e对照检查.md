# 渊下 · 与 D&D 5e 的机制对照检查

> 检查对象：建卡流程 + 规则引擎（rules.js / combat.js / run.js / items.js）+ 数据表
> 检查方式：`tools/check-data.mjs`、`tools/smoke.mjs` 全通过；另用 `tools/probe_5e.mjs`、`tools/probe_5e2.mjs`（定点实测）、`tools/probe_5e20.mjs`（20 级对照）、`tools/stress_lv20.mjs`（13 职业冲 20 级压测）做验证
> 结论分三类：**A = 真 bug（不是简化，会玩坏）**、**B = 与 5e 有出入（多为有意抽象化）**、**C = 完全对齐**

> **【2026-10-09 第二轮：已按 5e 大改，见第六节「本轮实装记录」】**
> 等级上限 **10 → 20**；A1~A6 六项真 bug **全部修复**；契约槽、邪术师/诗人/游侠已知法术、法师准备、奥术恢复、戏法成长、专注体质豁免、2.3 职业资源、巨量伤害即死 **全部同步 5e**。
> 下面的 A/B/C 表保留「发现时的问题描述」，每行末尾用 **【已修 / 已同步 / 保留】** 标注当前状态。

---

## 〇、流程现状

建卡顺序：`种族 → 背景 → 职业 → 子职(1级子职) → 购点 → 技能 → 法术 → 起始装备 → 难度`
- 兼职页已删除（1 级无意义），职业页那句「关于兼职」说明也按你的意见删掉了。
- 局内：地图 → 战斗/事件/商店/休整/宝库 → 结算 → 升级选择 → Boss 推进下一幕。
- 升级选择队列：`子职 / 属性或专长 / 战斗风格 / 专精 / 法术 / 戏法 / 魔能祈愿 / 超魔 / 魔契恩泽 / 职业进阶`。
- 「职业进阶」页有主属性 ≥13 的门槛校验（只校验新职业）。
- **长休后新增「重选已准备法术」屏**（A6 实装），法师只能从法术书里挑，牧师/德鲁伊/圣武士/工匠从本职法术列表里挑。

## 一、A 类：真 bug —— **六项全部已修**

| # | 现象（发现时） | 修复方式 | 状态 |
|---|---|---|---|

## 四、遗留的取舍（未同步，均为有意保留）

B 类里仍然保留出入的，都是单机化/抽象化的必然结果，或明确为「局内节奏」服务：

1. **XP 曲线**：沿用自建快节奏表（20 级），不走 PHB 的 300/900/2700…
2. **兼职前提**：只校验新职业主属性 ≥13，不校验原职业
3. **工匠已准备数**：向上取整（略强）
4. **勇武诗人 L6 额外攻击**：未实装
5. **反应 / 借机攻击 / 掩护 / 推撞擒抱**：全部抽象成「远/中/近」位移 + 自动触发反应
6. **死亡豁免 / 力竭 / 法术成分 / 仪式施法**：单机化简化

### 踩坑（下次改同类代码要注意）
1. 改完 `data/*.json` **必须** `node tools/build-data.mjs`，否则表里读不到（曾因此误判「10 级法师三环法术位 = 0」）。
2. 新增 `pendingChoices` kind 或扩容数组后，**所有「解析循环」脚本都要同步**（smoke 的循环上限已提到 400）。
3. smoke/压测脚本的法术池判定要区分 `spellbook`：`cls.spellcasting.spellbook ? p.knownSpells : (prepared ? p.prepared : p.knownSpells)`，否则法师会一直往 `prepared` 里塞而不推进 `knownSpells`，死循环。
4. `slotsMax` 里玄奥秘术的计算要放在「无常规施法职业提前 return」**之前**，否则纯邪术师高环法术位为 0。
5. `hostileAdvantage()` 的返回值是掷法（`'adv'` / `'dis'`），不能直接 `if (...) mode = 'adv'`。
6. 5e 狂暴是**抗性**不是固定减值，`rageDr` 已被有意置 0，相关探针要断言 `p.resist`。
